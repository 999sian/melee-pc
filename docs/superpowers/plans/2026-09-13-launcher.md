# Melee-PC Launcher Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver the approved RmlUi launcher and reliable disc selection flow.
**Architecture:** A C entry point calls a C++ launcher before game initialization.
Disc inspection and verification use independent nod handles; preferences use
standard filesystem I/O. Aurora owns rendering and input.
**Tech Stack:** C/C++20, Aurora, SDL3, RmlUi, nod, OpenSSL EVP SHA-1.
**Spec:** ../specs/2026-09-13-launcher-design.md

## Global constraints

- Linux and Melee NTSC-U 1.02 (GALE01, revision 2).
- Keep positional/--dvd launches, --no-card, and explicit environment overrides.
- Decode compressed discs through nod; never hash container bytes for verification.
- Preserve existing local edits. Git commits require a configured author identity.

## Task 1: Disc and preference boundary

Files: create src/pc/launcher_data.hpp, src/pc/launcher_data.cpp,
tools/test_launcher_data.cpp; modify CMakeLists.txt.

Interfaces: `DiscInfo inspect_disc(const std::string&)` returns supported/error
and identity metadata; `Verification verify_disc(const std::string&,
std::atomic_bool&, std::atomic_uint&)` returns verified/mismatch/canceled/error.
`Preferences load_preferences(const std::filesystem::path&)` and
`bool save_preferences(const std::filesystem::path&, const Preferences&,
std::string&)` own persistence. Verification is not persisted: every new process
starts unverified, avoiding stale trust.

- [x] Write executable tests rejecting an empty/malformed image, wrong game,
  and unsupported revision. Create small synthetic GameCube header fixtures.
- [x] Test preference round-trip with spaces and quotes, missing config defaults,
  invalid scale, and an unwritable destination. Observe missing implementation failure.
- [x] Implement nod header/partition inspection with RAII handles. Accept only
  `memcmp(header.game_id, "GALE01", 6) == 0 && header.disc_version == 2`.
- [x] Source the full-disc reference SHA-1 from the public Redump DAT; verify
  through `nod_read` in bounded chunks with `EVP_DigestUpdate`. Check cancellation
  between reads, increment progress, and compare hex digest to the sourced literal.
- [x] Write preferences to a temporary sibling and rename only after successful
  flush/close; parse quoted paths and bounded settings without throwing.
- [x] Build and run `launcher_data_test`; record results.

## Task 2: Launcher and startup handoff

Files: create src/pc/launcher.h, src/pc/launcher.cpp, resources/launcher.rml,
resources/launcher.rcss, resources/font.ttf and font license; modify
src/pc/main.c and CMakeLists.txt.

Interface: `void pc_launcher_configure(AuroraConfig*)` loads preferences before
Aurora initialization; `int pc_launcher_run(const char*, SDL_Window*)` returns
1 with an opened disc, 0 on quit, -1 on setup error. Caller only starts game on 1.

- [x] Add a no-disc startup/close integration check based on the existing X11
  window-close test; confirm the old executable exits before opening a window.
- [x] Enable RmlUi in CMake and package resources beside the executable. Resolve
  them with `SDL_GetBasePath()`; use a font with included redistribution license.
- [x] Build an RML layout with Play, Choose Disc, Verify/Cancel, Settings, Quit,
  a disc status card, clear focus styling, and responsive spacing.
- [x] Implement SDL dialog callback ownership using shared pending state; worker
  threads return data only. Main thread updates RmlUi. Join workers before exit.
- [x] Wire keyboard/controller navigation and settings toggles. Persist chosen
  valid paths; retain current selection on cancel/failure. Display errors as text.
- [x] Make main initialize Aurora before optional launcher; preserve CLI bypass
  for supported discs and fallback to launcher on errors. Close documents and
  complete frames before entering game code.
- [x] Build `melee`, run no-disc/invalid-disc close checks, and inspect actual UI.

## Execution results

Implemented in the existing checkout on `feat/rmlui-launcher`, preserving the
pre-existing port edits. Commits remain unavailable because Git author identity
is unset. Full verification uses OpenSSL EVP and Aurora's exported DVD target.

Build, data tests, seven desktop behavior cases, and scaled/small-window visual
checks passed. Native picker cancellation could not be validated: the forced
Zenity backend produced a blank/unresponsive window in this tool environment.
Physical controller navigation was not exercised. These are outstanding
acceptance checks, not claimed passes. See `docs/launcher-validation.md`.
